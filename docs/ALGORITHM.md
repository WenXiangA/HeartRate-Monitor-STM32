# 心率算法设计与验证

本文件记录 `software/stm32/user/api/adc.c` 中脉搏检测算法的设计要点与仿真验证结果。

## 一、算法参数

| 参数 | 取值 | 含义 |
| ---- | ---- | ---- |
| `WINDOW_SIZE` | 250 | 滑动窗口样本数：250 × 10ms = 2.5s |
| `SAMPLE_PERIOD_MS` | 10 | `get_BPM()` 调用周期，需与 main.c 时间片一致 |
| `PULSE_TIMEOUT` | 250 | 无脉搏超时：250 × 10ms = 2.5s |
| `BPM_MIN` / `BPM_MAX` | 30 / 200 | 有效心率范围（闭区间） |
| `SIGNAL_MIN_AMPL` | 20 | 判定"有脉搏"的最小信号幅度（ADC LSB） |

## 二、设计要点

### 1. 滑动窗口与阈值

窗口填满后转为环形缓冲，每 `WINDOW_SIZE` 个样本刷新一次 `max` / `min`，
判定阈值取窗口中值 `mid = (max + min) / 2`。信号从低于 `mid` 跳变到高于 `mid`
即为一次心搏（上升沿）。

窗口取 2.5s 是为了覆盖最低心率（30 BPM，周期 2s）的完整心动周期；
若窗口短于心动周期，会出现整窗无脉搏而被误判为"信号弱"。

### 2. 心搏间隔测量

**每个上升沿都清零 `timeCount`**，因此 `timeCount` 直接就是"距上次脉搏的间隔"：

```
IBI = timeCount × SAMPLE_PERIOD_MS
BPM = 60000 / IBI
```

早期版本每两次脉搏才清零一次，`timeCount` 累计的是两个心搏间隔，
在 40 BPM 附近会撞上 2.5s 超时而自我重置，导致低心率测不出来。

### 3. 状态机

| 状态 | 行为 |
| ---- | ---- |
| `window_ready == 0` | 上电预热，窗口未填满，不检测 |
| `signal_ok == 0` | 信号幅度过小（未佩戴/手指未放好），只清显示值并重新对齐，**不重置窗口** |
| `timeCount > PULSE_TIMEOUT` | 2.5s 无脉搏，归零并重新预热 |

信号过弱时不重置窗口是关键：低心率下窗口经常出现无脉搏的段落，
若此时强制重新预热，会陷入"预热 → 判定弱 → 再预热"的死循环，永远出不了数。

## 三、仿真验证

`verify/bpm_fix_verify.py` 把算法逐行等价翻译成 Python，
喂入模拟的 PPG（光电容积脉搏波）信号进行验证。

| 项目 | 结果 |
| ---- | ---- |
| 检出区间 | 30 / 40 / 50 / 60 / 72 / 90 / 120 / 150 / 180 / 200 BPM 全部检出 |
| 稳态误差 | < 1 BPM |
| 有效输出占比 | 100%（30~200 BPM 全区间） |
| 误报 | 传感器未佩戴（平直信号）时检测次数为 0，无误报 |

运行方式：

```bash
python verify/bpm_fix_verify.py
```
